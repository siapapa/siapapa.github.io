## A. 일반 소프트웨어 용어

### API
**한 줄**: 다른 회사·서비스의 기능을 코드로 부르는 창구.
**비유**: 콜센터 전화번호. 내가 "이거 해줘" 하고 요청하면 저쪽이 결과를 돌려줍니다.
**처음 만나는 곳**: Day 1 1H — OpenAI API, Day 4 21H — LangSmith API.

### API Key
**한 줄**: 그 창구를 쓰기 위한 개인 비밀번호.
**비유**: 아파트 출입카드. 분실 시 새로 발급받아야 합니다.
**처음 만나는 곳**: 사전 준비 — `OPENAI_API_KEY`, `LANGSMITH_API_KEY`, `COHERE_API_KEY`.

### 패키지 / 라이브러리 (package / library)
**한 줄**: 누가 이미 만들어 둔 코드 묶음. `pip install` 로 가져옵니다.
**비유**: 레고 키트 한 박스. 일일이 부품을 깎지 않고 박스째로 갖다 씁니다.
**처음 만나는 곳**: Day 1 1H — `!pip install langchain ...`.

### `import`
**한 줄**: "이 노트북에서 이 패키지/모듈을 쓰겠다" 는 선언.
**비유**: 박스를 책상 위에 꺼내 놓는 동작.
**처음 만나는 곳**: 모든 노트북 첫 셀.

### 변수 (variable)
**한 줄**: 값에 이름표를 붙여 두는 것. `x = 5` 면 `x` 라는 이름표를 5에 붙임.
**비유**: 책장에 라벨을 붙이기.
**처음 만나는 곳**: Day 1 2H 부터 어디서나.

### 함수 (function)
**한 줄**: 입력을 받아 어떤 작업을 한 뒤 결과를 돌려주는 코드 묶음. `f(x)` 의 그것.
**비유**: 자판기. 동전(입력)을 넣으면 음료(출력)가 나옵니다.
**처음 만나는 곳**: Day 1 2H — `run_query(sql)` 도우미 함수.

### 클래스 (class)
**한 줄**: "이런 모양의 데이터+동작" 을 미리 만들어 둔 설계도. 그 설계도로 만든 실제 물건이 **객체(instance)**.
**비유**: 와플 기계 = 클래스, 만들어진 와플 한 장 = 객체.
**처음 만나는 곳**: Day 1 5H — `Document(...)`, Day 3 15H — `BaseModel`.

### 메서드 (method)
**한 줄**: 클래스/객체에 붙어 있는 함수. `app.invoke(...)` 처럼 점 뒤에 오는 것.
**비유**: 자판기에 달린 버튼들 (구매 버튼·반환 버튼·환불 버튼).
**처음 만나는 곳**: Day 3 15H — `chain.invoke / stream / batch`.

### 에러 / 예외 (error / exception)
**한 줄**: 코드 실행 중 잘못된 상황. 빨간 글씨로 출력됩니다.
**비유**: 자판기가 "거스름돈 부족" 표시를 띄우는 것. **잘못한 게 아니라 안내문**.
**처음 만나는 곳**: 어디서나. → [비개발자 가이드의 에러 표 참고](../beginners-guide.md#3-3)

### Jupyter Notebook / Colab
**한 줄**: 코드와 글을 한 페이지에 섞어 쓰는 "코딩 노트". Colab 은 구글이 클라우드로 돌려주는 무료 버전.
**비유**: 워드 문서에 계산기를 박아 넣은 것.
**처음 만나는 곳**: 사전 준비.

### 셀 (cell)
**한 줄**: 노트북의 한 칸. 코드 셀(`▶` 로 실행) 또는 마크다운 셀(글씨용).
**처음 만나는 곳**: 사전 준비.

### `pip install`
**한 줄**: 패키지를 인터넷에서 받아와서 깔아주는 명령.
**비유**: 앱스토어에서 앱 설치.
**처음 만나는 곳**: 모든 노트북 첫 셀의 `!pip install -q ...`.

### `!` (느낌표) — 셸 명령 prefix
**한 줄**: 노트북 셀 맨 앞의 `!` 는 "이 줄은 파이썬이 아니라 터미널 명령" 이라는 표시.
**처음 만나는 곳**: `!pip install`, `!apt-get install`.

## B. 데이터·SQL·DB 용어

### 데이터베이스 (DB)
**한 줄**: 데이터를 안전하게 보관하고 빠르게 검색하게 해주는 전문 저장소.
**비유**: 잘 정리된 도서관. 엑셀이 노트라면 DB는 도서관 시스템.
**처음 만나는 곳**: Day 1 2H.

### 테이블 (table)
**한 줄**: DB 안의 한 장표. 행(row) × 열(column) 구조.
**비유**: 엑셀 시트 한 장.
**처음 만나는 곳**: Day 1 2H — `patients`, `doctors`, `visits` 등.

### 행(row) / 컬럼(column)
**한 줄**: 행 = 데이터 한 건. 컬럼 = 그 데이터의 항목들.
**비유**: 엑셀의 가로줄(행) / 세로줄(열).

### 스키마 (schema)
**한 줄**: 테이블·컬럼·관계의 **설계도**. "어떤 데이터가 어떻게 생겼는지".
**비유**: 건물 설계도. 실제 데이터는 그 도면대로 들어찬 살림.
**처음 만나는 곳**: Day 1 2H, 4H.

### DDL (Data Definition Language)
**한 줄**: 테이블을 만들고 바꾸고 지우는 SQL 명령어들. `CREATE TABLE`, `ALTER`, `DROP`.
**비유**: 건축 도면을 그리고 고치는 작업 (DML 은 도면 위에서 실제 살림을 옮기는 작업).
**처음 만나는 곳**: Day 1 2H.

### DML (Data Manipulation Language)
**한 줄**: 데이터를 넣고/바꾸고/지우는 SQL. `INSERT`, `UPDATE`, `DELETE`, `SELECT`.
**처음 만나는 곳**: Day 1 2H.

### Primary Key (PK)
**한 줄**: 그 행을 고유하게 식별하는 컬럼. 환자번호·주문번호 같은 것.
**비유**: 주민등록번호.

### Foreign Key (FK, REFERENCES)
**한 줄**: "이 컬럼의 값은 다른 테이블의 PK 에 반드시 존재해야 한다" 는 약속.
**비유**: 주문서에 적힌 회원번호가 회원 명부에 실제로 있어야 하는 것.
**처음 만나는 곳**: Day 1 2H — `department_id INT REFERENCES departments(department_id)`.

### `JOIN`
**한 줄**: 여러 테이블을 공통 컬럼으로 이어 붙여 한 화면에 보는 것.
**비유**: 주문서 + 회원 명부를 회원번호로 짝지어 합치기.
**처음 만나는 곳**: Day 1 3H.

### `GROUP BY`
**한 줄**: "같은 값끼리 묶어서 통계 내기".
**비유**: 엑셀의 피벗 테이블.
**처음 만나는 곳**: Day 1 3H.

### CTE (`WITH ... AS`)
**한 줄**: 쿼리 안에서 임시로 이름 붙인 중간 결과 테이블.
**비유**: 긴 계산식을 풀기 전에 메모지에 중간값을 적어두는 것.
**처음 만나는 곳**: Day 1 3H.

### 윈도우 함수 (window function)
**한 줄**: 행을 그룹으로 묶지 않고 **유지한 채로** 그 행 옆에 통계값을 붙이는 SQL 기능.
**비유**: 반 평균을 각 학생 옆 칸에 적어 넣기.
**처음 만나는 곳**: Day 1 3H.

### `EXPLAIN`
**한 줄**: SQL 이 내부적으로 어떤 순서로 실행될지 설명해 주는 도구.
**비유**: 내비게이션의 "예상 경로 보기".
**처음 만나는 곳**: Day 1 2H.

### PostgreSQL
**한 줄**: 오픈소스로 가장 널리 쓰이는 관계형 DB. 표준 SQL 준수도가 높음.
**처음 만나는 곳**: Day 1 2H.

### Neon
**한 줄**: 클라우드에서 무료로 PostgreSQL 인스턴스를 띄워 주는 서비스. 본 강의의 DB 호스트.
**처음 만나는 곳**: 사전 준비.

### DSN / Connection String
**한 줄**: DB 접속 주소. `postgresql://user:pw@host/db?sslmode=require` 형식.
**비유**: 전화번호 + 내선번호 + 비밀번호 가 합쳐진 한 줄.
**처음 만나는 곳**: 사전 준비 — `NEON_DSN`.

### `?sslmode=require`
**한 줄**: "이 접속은 암호화 통신만 허용" 이라는 옵션. 빠지면 Neon 접속이 실패함.
**처음 만나는 곳**: 사전 준비. (가장 흔한 Day 1 트러블)

### `psycopg2` / `SQLAlchemy`
**한 줄**: Python 에서 PostgreSQL 에 접속하기 위한 두 라이브러리. SQLAlchemy 가 더 상위 수준.
**비유**: psycopg2 = 직통 케이블, SQLAlchemy = 전원·USB·HDMI 묶은 도킹스테이션.
**처음 만나는 곳**: Day 1 2H.

### Engine / Connection (SQLAlchemy)
**한 줄**: `engine = create_engine(DSN)` 는 "DB 와 통화할 전용 회선 묶음" 을 미리 만들어 두는 것.
**비유**: 회사 내선 전화기를 책상 위에 비치한 상태.
**처음 만나는 곳**: 사전 준비 — 부트스트랩 코드.

### `text()`
**한 줄**: SQL 문자열을 SQLAlchemy 가 안전하게 실행할 수 있는 객체로 감싸는 함수.
**처음 만나는 곳**: Day 1 2H — `conn.execute(text(sql))`.

### `pandas` / DataFrame
**한 줄**: Python 의 표 데이터 처리 라이브러리. `df = pd.read_sql(...)` 결과가 DataFrame.
**비유**: 엑셀 시트를 변수로 들고 다니는 것.
**처음 만나는 곳**: Day 1 2H.

### `COMMENT ON`
**한 줄**: PostgreSQL 에서 테이블·컬럼에 주석을 다는 명령. **AI 가 스키마를 이해하는 데 결정적**.
**비유**: 엑셀 컬럼명 옆에 작은 메모를 붙이기.
**처음 만나는 곳**: Day 1 2H, 4H.

## C. AI · LLM · 임베딩

### LLM (Large Language Model)
**한 줄**: 인터넷급 텍스트로 학습한 거대한 언어 모델. ChatGPT, Claude 등.
**비유**: 책 수백만 권을 읽은 도서관 사서.
**처음 만나는 곳**: Day 1 1H.

### Token (토큰)
**한 줄**: LLM 이 글자를 잘라서 다루는 최소 단위. 한 단어가 1~3개 토큰일 수 있음.
**비유**: 글을 음절·조각 단위로 잘라 읽는 것.
**처음 만나는 곳**: Day 1 5H, Day 4 21H 비용 추적.

### Prompt (프롬프트)
**한 줄**: LLM 에게 주는 지시문/질문.
**비유**: 사서에게 건네는 질문 카드.
**처음 만나는 곳**: Day 1 1H.

### Temperature
**한 줄**: LLM 답변의 창의성/무작위성. 0 = 매번 같은 답, 1 = 다양/창의.
**비유**: 음식점에서 "정확히 메뉴대로(0)" vs "셰프 마음대로(1)".
**처음 만나는 곳**: Day 1 5H — `temperature=0`.

### Hallucination (할루시네이션, 환각)
**한 줄**: LLM 이 사실이 아닌 내용을 그럴듯하게 만들어내는 현상.
**비유**: 사서가 모르는 책 제목을 자신 있게 지어내는 것.
**처음 만나는 곳**: Day 1 5H, Day 4 22H (Faithfulness 메트릭).

### `gpt-4o-mini`
**한 줄**: OpenAI 의 저비용·고속 모델. 본 강의의 기본 모델.
**처음 만나는 곳**: 모든 노트북.

### Embedding (임베딩)
**한 줄**: 텍스트를 의미를 보존하는 **숫자 벡터**(예: 1536개의 수)로 변환한 것.
**비유**: 단어/문장에 위·경도 좌표를 부여하기. "고양이"와 "강아지"는 가깝고, "고양이"와 "철근"은 멀리.
**처음 만나는 곳**: Day 1 6H.

### 코사인 유사도 (cosine similarity)
**한 줄**: 두 벡터가 얼마나 비슷한 방향을 가리키는지 -1~1 로 나타낸 값. 1 에 가까울수록 비슷.
**비유**: 두 화살표가 같은 쪽을 향하는 정도.
**처음 만나는 곳**: Day 1 6H.

### 벡터 DB / Vector Store
**한 줄**: 임베딩을 저장하고 "비슷한 것 Top K 개 찾기" 가 빠른 특수 DB.
**예시**: ChromaDB, Pinecone, Weaviate.
**처음 만나는 곳**: Day 1 6H — ChromaDB.

### Chunk (청크) / Chunking
**한 줄**: 긴 문서를 검색하기 좋은 작은 조각으로 자르는 것.
**비유**: 두꺼운 책을 페이지·문단 단위로 잘라 색인 카드를 만드는 것.
**처음 만나는 곳**: Day 1 5H — `SentenceSplitter`.

### Top-K
**한 줄**: 검색 결과 중 가장 유사한 K 개만 가져오기.
**처음 만나는 곳**: Day 1 5H — `similarity_top_k=3`.

### Function Calling (도구 호출)
**한 줄**: LLM 이 자연어 답변 대신 **정해진 함수 인자(JSON)** 형태로 응답하게 하는 OpenAI 기능. 구조화 출력의 핵심.
**비유**: "자유 작문" 대신 "표 양식에 칸 채우기" 를 시키는 것.
**처음 만나는 곳**: Day 3 15H — `with_structured_output(method="function_calling")`.

## D. RAG · LlamaIndex · ChromaDB

### RAG (Retrieval-Augmented Generation)
**한 줄**: "관련 자료를 찾아 LLM 에게 같이 건네주고 답을 생성" 하는 구조. 할루시네이션을 줄이는 핵심 기법.
**비유**: 오픈북 시험. 사서가 시험 직전에 관련 페이지를 뽑아 줍니다.
**처음 만나는 곳**: Day 1 5H.

### LlamaIndex
**한 줄**: RAG 5단계(로딩 → 청킹 → 임베딩 → 인덱싱 → 질의)를 묶어 주는 파이썬 프레임워크.
**비유**: RAG 부엌 풀세트. 칼·도마·냄비를 따로 사지 않아도 한 번에.
**처음 만나는 곳**: Day 1 5H.

### Document / Node (LlamaIndex 용어)
**한 줄**: Document = 원본 문서 한 덩어리, Node = 그것을 청킹한 작은 조각.
**처음 만나는 곳**: Day 1 5H.

### Settings 객체 (LlamaIndex)
**한 줄**: "이 노트북 전체에서 쓸 LLM/임베딩 모델은 이거" 라고 한 번에 정해 두는 전역 설정.
**비유**: 사무실 공통 프린터를 미리 지정해 두기.
**처음 만나는 곳**: Day 1 5H.

### Index / VectorStoreIndex
**한 줄**: 임베딩 + 메타데이터 + 검색 기능을 합친 객체. `index.as_query_engine()` 으로 질의 가능.
**처음 만나는 곳**: Day 1 5H.

### Query Engine vs Retriever
**한 줄**: Query Engine = 검색 + LLM 답변 생성. Retriever = 검색만 (LLM 호출 없음).
**비유**: Query Engine = 풀코스. Retriever = 재료 갖다 주기까지만.
**처음 만나는 곳**: Day 1 5H.

### ChromaDB
**한 줄**: 가벼운 오픈소스 벡터 DB. 인메모리·디스크 양쪽 지원.
**처음 만나는 곳**: Day 1 6H.

### Persist (영속화)
**한 줄**: 메모리에만 있던 데이터를 디스크에 저장해 두기. 노트북을 재시작해도 살아남음.
**처음 만나는 곳**: Day 1 6H.

### NLSQLTableQueryEngine

**처음 만나는 곳**: Day 1 7H, Day 2 10H.

### Text-to-SQL
**한 줄**: 자연어 질문을 SQL 로 변환하는 작업의 **카테고리 이름**.
**처음 만나는 곳**: Day 1 7H.

### Schema Intelligence (스키마 지능)
**한 줄**: AI 가 스키마를 잘 이해하도록 **이름·주석·관계** 를 다듬는 설계 원칙.
**처음 만나는 곳**: Day 1 4H.

## E. LangChain · LCEL · Pydantic · LangGraph

### LangChain
**한 줄**: LLM 앱 개발 표준 프레임워크. "프롬프트·모델·파서·체인" 을 일관된 인터페이스로 묶음.
**처음 만나는 곳**: Day 3 15H.

### LCEL (LangChain Expression Language)
**한 줄**: `prompt | model | parser` 처럼 파이프(`|`) 로 체인을 조립하는 LangChain 의 문법.
**비유**: 유닉스 파이프 `cat | grep | wc` 의 LangChain 버전.
**처음 만나는 곳**: Day 3 15H.

### `|` 연산자 (LangChain)
**한 줄**: 파이썬 비트 OR 가 아니라 LangChain 이 재정의한 "이 단계 출력 → 다음 단계 입력" 기호.
**처음 만나는 곳**: Day 3 15H.

### Runnable
**한 줄**: LangChain 의 모든 부품이 따르는 공통 규약. `invoke / stream / batch` 메서드를 가짐.
**비유**: 모든 부품이 USB-C 단자를 갖고 있어서 자유롭게 끼워지는 것.
**처음 만나는 곳**: Day 3 15H.

### `invoke / stream / batch`
**한 줄**: 각각 단건 실행 / 스트리밍(글자가 흘러나옴) / 여러 입력 동시 실행.
**처음 만나는 곳**: Day 3 15H.

### `RunnablePassthrough` / `RunnableLambda` / `RunnableParallel`
**한 줄**: 각각 (그대로 통과) / (커스텀 함수 끼우기) / (여러 체인 동시 실행) 유틸.
**처음 만나는 곳**: Day 3 15H, 16H.

### Pydantic / `BaseModel`
**한 줄**: 파이썬 객체에 "필드와 타입을 검증하는 양식" 을 부여하는 라이브러리.
**비유**: 일반 dict 가 자유 메모지라면, Pydantic 은 칸이 정해진 양식 폼.
**처음 만나는 곳**: Day 3 15H.

### `Field(description=...)`
**한 줄**: Pydantic 필드에 LLM 이 읽을 설명을 붙이는 도구. 구조화 출력에 결정적.
**처음 만나는 곳**: Day 3 15H.

### `with_structured_output`
**한 줄**: LLM 응답을 자유 텍스트가 아닌 **Pydantic 스키마 인스턴스** 로 받게 하는 LangChain API.
**비유**: 작문 답안 대신 시험지 양식으로 답하게 시키기.
**처음 만나는 곳**: Day 3 15H.

### `JsonOutputParser`
**한 줄**: 구조화 출력의 대안. 프롬프트에 "JSON 으로 답해" 지시를 넣고 결과를 파싱.
**처음 만나는 곳**: Day 3 15H.

### Streaming (스트리밍)
**한 줄**: LLM 응답을 한꺼번에 받지 않고 토큰 단위로 흘려 받기. 채팅 UI 의 "타이핑 효과".
**처음 만나는 곳**: Day 3 15H, Day 2 12H Gradio.

### `TypedDict`
**한 줄**: 파이썬 dict 의 **키와 값 타입을 미리 선언** 하는 가벼운 타입 힌트. LangGraph State 정의에 사용.
**비유**: 자유 메모지에 "이름 칸·나이 칸·주소 칸" 을 미리 그어두기.
**처음 만나는 곳**: Day 3 19H.

### LangGraph
**한 줄**: 상태 머신(FSM) 으로 LLM 워크플로우를 그리는 프레임워크. LCEL 의 한계(루프·재시도) 를 해결.
**비유**: LCEL = 파이프라인, LangGraph = 신호등이 있는 도로망.
**처음 만나는 곳**: Day 3 19H.

### StateGraph
**한 줄**: LangGraph 의 그래프 객체. 노드(함수) + 엣지(연결) + 조건 분기로 흐름을 구성.
**처음 만나는 곳**: Day 3 19H.

### Node (LangGraph)
**한 줄**: State 를 받아 변경할 부분만 dict 로 반환하는 함수.
**처음 만나는 곳**: Day 3 19H.

### Edge / Conditional Edge
**한 줄**: 노드 간 연결. Conditional 은 함수의 반환값에 따라 다른 노드로 분기.
**처음 만나는 곳**: Day 3 19H.

### FSM (Finite State Machine, 유한 상태 머신)
**한 줄**: 정해진 몇 개의 상태와 그 사이 전이 규칙으로 동작하는 모델.
**비유**: 신호등(빨강·노랑·초록 + 전이 규칙).
**처음 만나는 곳**: Day 3 19H.

### Checkpointer
**한 줄**: LangGraph 가 매 단계 상태를 저장해 두어 **중단 후 이어서 실행** 하게 해주는 장치.
**처음 만나는 곳**: Day 3 19H (심화).

### ReAct 에이전트
**한 줄**: "Reason(추론) → Act(도구 호출) → Observe(결과 보기)" 루프를 도는 에이전트 패턴.
**처음 만나는 곳**: Day 3 19H, 20H.

## G. Advanced RAG (Day 3 17~18H)

### HyDE (Hypothetical Document Embedding)
**한 줄**: 질문 그 자체가 아닌 **"이 질문에 답하는 가상 문서"** 를 LLM 에게 만들게 한 뒤 그것을 임베딩해 검색.
**비유**: "이 책을 어디서 봤더라" 대신 "이 책 내용이 이럴 거야" 를 떠올려 책장에서 비슷한 걸 찾는 것.
**처음 만나는 곳**: Day 3 17H.

### Multi-Query
**한 줄**: 한 질문을 LLM 으로 여러 변형 질문으로 만들어 동시에 검색 → 결과 합치기.
**처음 만나는 곳**: Day 3 17H.

### Query Decomposition
**한 줄**: 복잡한 질문을 더 작은 하위 질문들로 분해하여 각각 검색.
**처음 만나는 곳**: Day 3 17H.

### BM25
**한 줄**: 단어 빈도 기반의 고전적 검색 알고리즘. 정확한 단어 매칭에 강함.
**비유**: 도서관 카드 색인.
**처음 만나는 곳**: Day 3 18H.

### Hybrid Search (하이브리드 검색)
**한 줄**: BM25(키워드) + 벡터(의미) 두 결과를 합쳐 점수 매기기.
**처음 만나는 곳**: Day 3 18H.

### Re-rank / CrossEncoder / Cohere Re-rank
**한 줄**: 1차 검색 결과 상위 N 개를 더 정밀한 모델로 다시 정렬하는 단계.
**비유**: 1차 면접 통과자만 임원 면접에 올리기.
**처음 만나는 곳**: Day 3 18H.

### Parent-Child 청킹
**한 줄**: 작은 청크로 검색하되, LLM 에게는 그 청크가 속한 더 큰 부모 청크를 건네주기.
**처음 만나는 곳**: Day 3 18H.

### Ragas
**한 줄**: RAG 시스템을 정량 평가하는 라이브러리. 4개 핵심 메트릭 제공.
**처음 만나는 곳**: Day 4 22H.

### Faithfulness (충실도)
**한 줄**: 답변이 검색된 컨텍스트 안의 사실에 충실한가 (할루시네이션 방지 지표).
**비유**: 시험 답안이 오픈북 자료에서 벗어나지 않았는가.
**처음 만나는 곳**: Day 4 22H.

### Answer Relevancy (답변 적절성)
**한 줄**: 답변이 질문에 실제로 답했는가.
**비유**: 동문서답이 아닌가.
**처음 만나는 곳**: Day 4 22H.

### Context Precision (검색 정밀도)
**한 줄**: 검색해서 가져온 자료 중 진짜 관련 있는 것의 비율.
**비유**: 도서관 사서가 가져온 10권 중 실제 시험에 도움 되는 책의 비율.
**처음 만나는 곳**: Day 4 22H.

### Context Recall (검색 재현율)
**한 줄**: 정답에 필요한 자료 중 사서가 빠뜨리지 않고 가져온 비율.
**비유**: 시험에 꼭 필요한 책 5권 중 몇 권을 사서가 챙겨 왔는가.
**처음 만나는 곳**: Day 4 22H.

### Ground Truth / Reference
**한 줄**: 사람이 만든 정답 라벨. Ragas 평가의 기준.
**처음 만나는 곳**: Day 4 22H.

## I. 안전·운영 패턴

### 가드레일 (Guardrail)
