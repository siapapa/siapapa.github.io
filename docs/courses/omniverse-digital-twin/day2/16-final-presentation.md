# 16H · 최종 발표 & 수료

## 발표 형식

**1인 5~7분** · 라이브 데모 + 상호 피드백

슬라이드는 3장이면 충분합니다.

| 장 | 내용 |
|---|---|
| 1 | **문제** — 어떤 설비의 어떤 질문인가 |
| 2 | **아키텍처** — 씬 구조와 데이터 흐름 |
| 3 | **결과** — 숫자로 답한 것, 그리고 한계 |

---

## 반드시 보여 줄 네 가지

### 1. USD 씬 — 레이어가 2장 이상 분리

Layer 창을 열어 구조를 보여 주세요.
왜 그렇게 나눴는지 한 문장으로 설명하면 좋습니다.

### 2. 데이터 연동 — 값이 흘러 들어와 씬이 반응

타임라인을 재생하고, Property 패널에서 값이 변하는 것을 보여 주세요.

### 3. 상태 시각화 — 정상/경고/이상이 눈으로 구분

고장 시점으로 이동해 색이 바뀌는 것을 보여 주세요.

### 4. 질문 1개에 대한 답 ★

과제 #1 에서 던진 질문 중 하나를 **트윈으로 답해** 보이세요.

!!! quote "이것이 발표의 중심입니다"
    "예쁘게 만들었습니다" 가 아니라
    **"이 질문에 이렇게 답했습니다"** 가 되어야 합니다.

---

## 평가 루브릭

| 항목 | 비중 | 무엇을 보는가 |
|---|:---:|---|
| 과제 #1 (제안서) | 20% | 질문이 데이터로 답할 수 있는 형태인가 |
| 과제 #2 (데이터 연동) | 20% | 데이터가 실제로 씬을 움직이는가 |
| 최종 산출물 | 35% | 레이어 구조·시각화·완성도 |
| 발표 | 15% | **문제 정의와 한계를 스스로 설명하는가** |
| 참여·피어리뷰 | 10% | — |

!!! success "'한계를 설명하는가' 에 배점이 실려 있습니다"
    잘 만든 사람보다 **자기가 만든 것의 한계를 정확히 아는 사람**이
    현장에서 쓸모 있습니다.

    - 모의 데이터로 했다는 것
    - 형상이 실제 설비와 다르다는 것
    - 실제 적용하려면 무엇이 더 필요한지

    이런 것을 말할 수 있으면 좋은 발표입니다.

## 2일 동안 배운 것

| Day | 무엇 |
|---|---|
| **1** | 씬은 파일이다 · 파일은 여러 장으로 나뉜다 · 자동화와 검증 |
| **2** | 물리 · 실시간 데이터 · 상태 시각화 · what-if |

### 성숙도 어디까지 왔나

1H 에서 본 세 단계를 다시 봅시다.

| 단계 | 오늘 |
|---|---|
| Digital Model | 첫날 오전에 통과 |
| **Digital Shadow** | ✅ **여기까지 왔습니다** |
| Digital Twin | 아직 — 아래 참조 |

### Twin 으로 가려면 무엇이 더 필요한가

| 필요한 것 | 왜 |
|---|---|
| **실제 데이터 연결** | 모의 데이터가 아닌 실제 PLC·센서 |
| **되먹임 경로** | 모델의 판단을 설비에 반영하는 통로 |
| **정확도 검증** | 모델 예측과 실제가 얼마나 맞는지 |
| **운영 체계** | 누가 보고 누가 조치하는가 |

**기술보다 마지막 두 개가 어렵습니다.**

## 현장 적용을 생각한다면

1. **작게 시작하세요** — 라인 하나, 설비 몇 대
2. **질문부터 정하세요** — "무엇을 알고 싶은가" 없이 만들면 비싼 3D 뷰어가 됩니다
3. **데이터가 먼저입니다** — 태그가 없으면 트윈도 없습니다
4. **한 사람이 다 못 합니다** — 설비·데이터·3D 담당이 다릅니다.
   오늘 배운 **레이어 분리**가 그 협업 구조입니다
