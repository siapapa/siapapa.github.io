# 21H · 자연어로 묻기 — 진짜 주제는 가드레일

!!! success "이 시간은 실행 검증 완료 · GPU 불필요"
    LLM API 키가 없으면 **규칙 기반 폴백**으로 진행됩니다.

**실습 노트북**: `course_b/day3/28_nl_query.ipynb`

## 학습 목표

- 스키마를 LLM 이 이해할 형태로 요약한다
- 생성된 SQL 을 **실행하기 전에** 검증한다
- **SQL 이 맞아도 해석이 틀릴 수 있다**는 것을 안다

---

## LLM 이 SQL 을 만드는 것은 어렵지 않습니다

어려운 것은 **그 SQL 을 믿고 실행해도 되는가** 입니다.

| 위험 | 결과 |
|---|---|
| `DELETE` / `DROP` 생성 | 데이터 소실 |
| `LIMIT` 없는 전체 조회 | 메모리 폭발 |
| 여러 문장 (`;` 로 연결) | 의도치 않은 부작용 |
| 없는 테이블·컬럼 참조 | 런타임 오류 |

## 가드레일 ★

```python
def guard(sql: str) -> str:
    if "--" in sql or "/*" in sql:
        raise UnsafeSQL("주석이 포함된 SQL 은 허용되지 않습니다")
    if ";" in cleaned:
        raise UnsafeSQL("여러 문장은 허용되지 않습니다")
    if not re.match(r"^(select|with)\b", lowered):
        raise UnsafeSQL("SELECT/WITH 만 허용됩니다")
    ...
```

| 규칙 | 막는 것 |
|---|---|
| SELECT/WITH 로만 시작 | `DELETE` · `DROP` · `UPDATE` |
| 한 문장만 | `;` 로 붙인 부작용 |
| 알려진 테이블만 (**CTE 포함**) | 없는 테이블 · `UNION` 으로 훔쳐보기 |
| 주석 **거부** | 주석 해석 차이를 이용한 우회 |
| LIMIT 강제 | 메모리 폭발 |

### 주석은 제거가 아니라 거부합니다 ★

!!! quote "제거해서 통과시키면 구멍이 생깁니다"
    가드레일과 DB 가 **"무엇이 주석인가"를 다르게 볼 때** 우회가 가능해집니다.
    방언마다 `--` 뒤 공백 요구 여부 등이 다릅니다.

    LLM 이 만든 SQL 에 주석이 필요할 일은 없으므로
    **통째로 막는 편이 안전하고 단순합니다.**

    보안 설계에서 자주 쓰는 태도입니다 — **애매하면 거부.**

### 막는 것만큼 통과시키는 것도 설계해야 합니다 ★

!!! quote "이 교재를 만들 때 실제로 겪은 일"
    처음에 `WITH x AS (...) SELECT * FROM x` 질의가 **전부 막혔습니다.**
    `x` 가 허용 테이블 목록에 없었기 때문입니다.

    ```python
    # CTE 이름을 허용 목록에 더한다
    cte_names = set(re.findall(r"(?:with|,)\s+(\w+)\s+as\s*\(", lowered))
    unknown = referenced - ALLOWED_TABLES - cte_names
    ```

!!! danger "가드레일이 정상 사용을 막으면 사람들은 가드레일을 끕니다"
    그러면 아무것도 안 막은 것보다 나쁩니다 —
    "우리는 가드레일이 있다"고 믿기 때문입니다.

## 검증기를 검증하세요

```
■ 통과해야 하는 것
  ✅ SELECT * FROM sim_runs                          → LIMIT 있음
  ✅ SELECT preset, AVG(success) FROM ... GROUP BY   → LIMIT 있음
  ✅ WITH x AS (SELECT * FROM sim_runs) SELECT ...   → LIMIT 있음

■ 막아야 하는 것
  ✅ 차단 — 삭제문           SELECT/WITH 만 허용됩니다
  ✅ 차단 — 여러 문장         여러 문장은 허용되지 않습니다
  ✅ 차단 — 미지 테이블       허용되지 않은 테이블: ['users']
  ✅ 차단 — 주석 포함         주석이 포함된 SQL 은 허용되지 않습니다
```

## 가장 큰 위험 — 교란변수 ★

노트북에 **일부러 오해하기 쉬운 결과**를 넣어 두었습니다.

```
❓ 병렬 환경 수에 따라 성능이 달라지나요?
   num_envs | success_pct | runs
   256      | 88.8        | 2
   1024     | 58.9        | 3
   2048     | 20.8        | 1
```

"환경 수가 적을수록 좋다"로 읽힙니다. **13H 에서 배운 것과 반대입니다.**

`preset` 을 고정하고 다시 보면:

```
preset  | num_envs | success_pct
robust  | 256      | 88.8
robust  | 1024     | 87.5      ← 차이가 사라집니다
naive   | 1024     | 44.6
extreme | 2048     | 20.8
```

**`preset` 이 교란변수(confounder)** 였습니다.

!!! danger "SQL 은 정확히 물은 것을 답합니다"
    하지만 **물음 자체가 잘못됐는지는 알려 주지 않습니다.**

    LLM 이 만든 SQL 이 문법적으로 완벽해도 **해석은 사람 몫**입니다.
    자연어 질의의 가장 큰 위험이 여기 있습니다.
