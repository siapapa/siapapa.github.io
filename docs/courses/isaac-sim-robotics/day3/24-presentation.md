# 24H · 최종 발표 & 수료

**1인 7~10분** · 라이브 데모 + 상호 피드백

---

## 반드시 보여 줄 다섯 가지

### 1. 학습된 로봇 정책

커스텀 태스크에서 목표 동작이 나오는 것을 **실제로 재생**해 보이세요.

### 2. 보상 설계 근거 ★

각 항을 왜 넣었고 가중치를 왜 그렇게 정했는지.
**이것이 배점의 핵심입니다.**

### 3. 합성 데이터셋 + 비전 모델

도메인 랜덤화가 적용되어 있고, **운영 지표**(불량 유출·과검)로 보고.

### 4. 자연어 질의 데모

시뮬 결과를 DB 에서 자연어로 묻고 답이 나오는 것.

### 5. 한계 ★

sim2real 갭이 어디서 오는지, 실제 적용에 무엇이 더 필요한지.

---

## 평가 루브릭

| 항목 | 비중 | 무엇을 보는가 |
|---|:---:|---|
| 과제 #1 (씬·데이터셋) | 15% | 랜덤화 설계와 라벨 품질 |
| 과제 #2 (RL 태스크) | 15% | **보상 설계의 타당성**, 곡선 해석 |
| 과제 #3 (모델·적재) | 15% | 파이프라인이 끝까지 이어지는가 |
| 최종 산출물 | 30% | 완성도와 일관성 |
| 발표 | 15% | **한계와 개선 방향 설명** |
| 참여·피어리뷰 | 10% | — |

!!! success "배점의 핵심은 '왜' 입니다"
    곡선이 잘 올라간 것보다 **왜 그렇게 설계했는지**,
    성공률 91% 대신 87% 를 **왜 택했는지** 설명할 수 있는 쪽이
    현장에서 쓸모 있습니다.

## 3일 동안 배운 것

| Day | 무엇 |
|---|---|
| **1** | 로봇을 올리고 센서를 달고 합성 데이터를 만들었다 |
| **2** | 환경을 정의하고 보상을 설계해 정책을 학습시켰다 |
| **3** | 갭을 재고, DB 에 넣고, 자연어로 물었다 |

### 관통한 하나의 생각

!!! quote "시뮬을 현실과 똑같이 만들려 하지 말고, 어떤 현실에도 견디도록 만든다"
    Day 1 의 이미지 랜덤화, Day 3 의 물성 랜덤화 —
    **같은 원리를 다른 대상에** 적용한 것입니다.

### 반복해서 만난 교훈

| 교훈 | 어디서 |
|---|---|
| 지표 하나로 판단하지 않기 | 14H 보상 해킹 · 19H 운영 지표 |
| 검증기도 검증해야 함 | 8H 데이터 검수 · 21H 가드레일 |
| 조용한 오류가 가장 위험 | 6H 좌표계 · 16H 보상 0 |
| 해석은 사람 몫 | 21H 교란변수 |

---

## 현장 적용을 생각한다면

이 과정은 **전부 합성 데이터와 시뮬레이션**으로 했습니다.
실제 도입은 여기서부터입니다.

| 단계 | 무엇 |
|---|---|
| 1 | 실제 설비 3D 스캔 또는 CAD 확보 |
| 2 | 실 데이터 연동 (PLC · 센서) |
| 3 | **현장 이미지 일부로 재학습** — 합성만으로는 부족합니다 |
| 4 | 파일럿 라인 적용 · 사람 감시하에 |
| 5 | 운영 체계 수립 — 누가 보고 누가 조치하는가 |

!!! warning "3번을 건너뛰지 마세요"
    도메인 랜덤화는 갭을 **줄이는** 것이지 **없애는** 것이 아닙니다.
    현장 이미지 수백 장으로 미세조정하면 성능이 크게 올라갑니다.

## 40시간을 마치며

[기초 과정](../../omniverse-digital-twin/index.md) 16H 와 이 과정 24H 를
모두 마치셨다면 **40시간**을 이수하신 것입니다.

- 3D 모델에 데이터를 붙여 **살아 움직이는 트윈**을 만들었고
- 그 위에 로봇을 올려 **스스로 움직이는 법을 학습**시켰고
- 시뮬과 현실의 격차를 **숫자로 재고 판단**했습니다

수고하셨습니다. 🎓

자료는 계속 열려 있습니다. 실습 파일과 이 페이지들은 언제든 다시 보실 수 있습니다.
