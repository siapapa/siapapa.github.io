# 17H · sim-to-real 갭 — 로봇 편

!!! warning "이 시간의 실습은 최종 검증 전입니다"
    특히 물성 랜덤화 함수 이름이 버전에 따라 다를 수 있습니다.

**실습 스크립트**: `course_b/day3/24_sim2real.py`

## 학습 목표

- 갭의 원인을 분해한다
- 노이즈·지연·물성을 학습 중에 흔든다
- **평가를 서로 바꿔서** 하는 이유를 안다

---

## 갭의 원인

시뮬에서 성공률 95% 인 정책이 현장에서 20% 도 안 나옵니다.

| 원인 | 시뮬 | 현실 |
|---|---|---|
| 센서 노이즈 | 정확한 값 | 떨리고 튀는 값 |
| 제어 지연 | 즉시 반영 | 수십 ms 지연 |
| 물성 오차 | 정확한 질량·마찰 | 개체차·마모 |
| 미모델링 | 없음 | 케이블·백래시·진동 |

## 세 가지를 주입합니다

```python
PRESETS = {
    "naive":  {"obs_noise_std": 0.0,  "action_delay_steps": 0,
               "mass_range": (1.0, 1.0), "friction_range": (1.0, 1.0)},
    "robust": {"obs_noise_std": 0.01, "action_delay_steps": 1,
               "mass_range": (0.8, 1.2), "friction_range": (0.7, 1.3)},
    "extreme":{"obs_noise_std": 0.2,  "action_delay_steps": 5,
               "mass_range": (0.3, 3.0), "friction_range": (0.2, 3.0)},
}
```

| 프리셋 | 용도 |
|---|---|
| `naive` | 비교군 — 아무것도 안 흔듦 |
| **`robust`** | **권장 출발점** — 실제 오차 수준을 조금 넘게 |
| `extreme` | 과도하게 흔들면 아무것도 못 배운다는 것을 보여 주는 용도 |

!!! note "`enable_corruption` 을 켜야 노이즈가 실제로 적용됩니다"
    관측 항에 노이즈 모델을 붙여도 이 스위치가 꺼져 있으면 무시됩니다.
    자주 빠뜨리는 부분입니다.

## 평가를 서로 바꿔서 하세요 ★

!!! danger "같은 조건에서만 평가하면 갭이 안 보입니다"
    `naive` 정책을 `naive` 환경에서 재면 **항상 좋아 보입니다.**

```
1) naive / robust 두 프리셋으로 각각 학습
2) 두 정책을 서로 바꿔 평가:
     naive 정책  → robust 환경에서 평가   ← 여기서 무너집니다
     robust 정책 → robust 환경에서 평가
3) 26_measure_gap.ipynb 로 두 결과를 비교
```

**"학습 환경"과 "평가 환경"을 분리해서 생각하는 것**이 이 시간의 핵심입니다.
현장은 학습 환경과 다른 환경이니까요.

---

## 균형이 있습니다

| 랜덤화 | 결과 |
|---|---|
| 없음 | 시뮬 100%, 현장 붕괴 |
| **적당** | 시뮬 조금 낮아지고, **현장 크게 좋아짐** |
| 과도 | 시뮬도 현장도 학습 자체가 안 됨 |

`extreme` 프리셋으로 돌려 보면 세 번째 경우를 직접 볼 수 있습니다.

!!! tip "랜덤화는 만능이 아닙니다"
    "많이 흔들수록 좋다"가 아니라 **"실제 현장의 변동 폭을 조금 넘게"** 입니다.
    현장 조건을 모르면 랜덤화 범위도 정할 수 없습니다.
