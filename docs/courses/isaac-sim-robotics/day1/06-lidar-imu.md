# 6H · LiDAR · IMU — 진짜 주제는 정합

!!! warning "이 시간의 실습은 최종 검증 전입니다"
    LiDAR 클래스 이름이 버전에 따라 다릅니다.
    스크립트가 RTX/PhysX 두 갈래를 모두 시도합니다.

**실습 스크립트**: `course_b/day1/14_sensors_lidar_imu.py`

## 학습 목표

- LiDAR 와 IMU 의 데이터 형태를 안다
- **좌표계와 타임스탬프**를 왜 매번 확인해야 하는지 안다
- 자가 점검을 습관으로 만든다

---

## 센서를 다는 것은 쉽습니다

어려운 것은 여러 센서의 값을 **같은 시각·같은 좌표계**로 맞추는 것입니다.
여기서 틀리면 이후 모든 것이 **조용히** 틀립니다.

| 함정 | 증상 |
|---|---|
| 센서 좌표계 ≠ 로봇 좌표계 | 장애물이 **반대편에** 있다고 나옴 |
| 센서 주기 ≠ 물리 주기 | 같은 값이 여러 번 읽히거나 건너뜀 |
| 타임스탬프 미기록 | 나중에 센서 융합이 **불가능** |
| 업축 혼동 (Y-up/Z-up) | 바닥이 벽이 됨 |

!!! quote "조용히 틀린다는 것이 무섭습니다"
    에러가 나면 고칩니다. 그럴듯한 값이 나오면 몇 주 뒤에 발견합니다.

---

## 센서는 몸체의 자식으로

```python
lidar = LidarRtx(
    prim_path="/World/AGV/Lidar",           # ← AGV 의 자식
    translation=np.array([0.0, 0.0, 0.3]),  # 몸체 기준 상대 위치
)
```

**그래야 몸체가 움직일 때 따라옵니다.**
`translation` 은 몸체 기준 상대 좌표입니다 — 여기가 좌표계 함정의 시작점입니다.

## LiDAR 두 갈래

| 종류 | 특징 | 확장 |
|---|---|---|
| **RTX LiDAR** | 레이트레이싱. 사실적, 무거움 | `isaacsim.sensors.rtx` |
| **PhysX LiDAR** | 레이캐스트. 가볍고 단순 | `isaacsim.sensors.physx` |

!!! note "RTX LiDAR 는 렌더가 돌아야 데이터가 찹니다"
    `--headless` 로 실행하면 비어 있을 수 있습니다.
    처음에는 화면을 켜고 확인하세요.

## 타임스탬프를 반드시 함께 기록하세요 ★

```python
log.append({
    "step": step,
    "time": float(world.current_time),      # ← 이것이 없으면 나중에 융합 불가
    "pos": np.asarray(position).tolist(),
    "quat": np.asarray(orientation).tolist(),
    "lin_acc": np.asarray(imu_acc).tolist(),

```

!!! danger "'언제의 값인가' 가 없으면 센서 융합을 못 합니다"
    카메라 이미지와 LiDAR 점군을 맞추려면 같은 시각의 것이어야 합니다.
    나중에 추가하려 해도 이미 수집한 데이터에는 붙일 수 없습니다.

## 자가 점검 — 중력 정합 ★

스크립트가 마지막에 자동으로 확인합니다.

```
평균 선형가속도: [0.0, 0.0, -9.81]
가장 큰 성분: Z축 (-9.81)
✅ 중력이 Z축에 잡힙니다.
```

Z 가 아니면 업축이나 센서 방향이 틀린 것입니다.

!!! success "이런 자가 점검을 습관으로 만드세요"
    **로보틱스에서 가장 값싼 보험입니다.**

    - 중력이 아래를 향하는가
    - 로봇이 가만히 있을 때 속도가 0 인가
    - 센서 주기가 설정한 값과 맞는가

    이 세 가지만 확인해도 대부분의 좌표계·타이밍 문제가 잡힙니다.
