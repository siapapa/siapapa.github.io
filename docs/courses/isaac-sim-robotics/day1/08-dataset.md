# 8H · 데이터셋 — 양이 아니라 구성

!!! warning "생성 스크립트는 최종 검증 전입니다"
    `16_dataset_build.py` 는 Isaac Sim 이 필요하며 아직 실행 확인 전입니다.

!!! success "검수 노트북은 검증 완료 · GPU 불필요"
    `17_dataset_qc.ipynb` 는 실행 검증이 끝났습니다.
    Isaac Sim 이 없으면 **모의 데이터셋**을 만들어 검수 로직을 익힐 수 있습니다.

**실습 자산**: `16_dataset_build.py` · `17_dataset_qc.ipynb`

## 학습 목표

- 쓸 만한 데이터셋의 구성 요건을 안다
- 학습 전에 품질을 검수한다
- **검사에도 순서가 있다**는 것을 안다

---

## 실무에서 성능을 가르는 것

생성 기술이 아니라 **구성**입니다.

| 항목 | 안 하면 |
|---|---|
| **클래스 균형** | 불량 5% 데이터 → "전부 정상"이라 답해도 95% 정확도 |
| **train/val 분리** | 검증 점수가 부풀려짐 |
| **분할 시점** | 랜덤화 조건이 겹치면 val 이 train 을 훔쳐봄 |
| **재현성(seed)** | 실험 비교 불가 |
| **manifest** | 몇 달 뒤 이 데이터가 뭔지 아무도 모름 |

### 분할은 "조건" 단위로 ★

같은 랜덤화 시드에서 나온 이미지들은 서로 매우 비슷합니다.
이미지 단위로 무작위 분할하면 **거의 같은 그림이 양쪽에 들어가**
검증 점수가 실제보다 높게 나옵니다.

## 검수 없이 학습에 쓰지 마세요 ★

!!! danger "라벨이 전부 비어 있어도 학습은 '돌아갑니다'"
    손실값도 내려갑니다. 며칠 뒤 성능이 안 나오는 이유를 찾다가
    여기로 돌아오게 됩니다.

`17_dataset_qc.ipynb` 가 잡는 것:

| 검사 | 놓치면 |
|---|---|
| 라벨 없는 프레임 | 모델이 "아무것도 없음"을 학습 |
| 검은 / 균일 프레임 | 렌더 워밍업을 안 버린 것 (5H) |
| 이미지 밖 bbox | 좌표계·해상도 불일치 |
| 지나치게 작은 bbox | 물체가 화면 밖으로 나감 |
| 클래스 불균형 | 다수 클래스만 맞혀도 높은 정확도 |
| train/val 중복 | 검증 점수가 부풀려짐 |

### 실행 결과 예시

```
검사                           건수       비율
⚠️  라벨 파일 없음                   1     1.1%
❌ 라벨 비어 있음                  10    11.2%
⚠️  이미지 밖 bbox                 3     3.4%
❌ 검은 프레임                     9    10.1%
❌ train/val 누수                 1     1.1%

총 프레임 89 · 문제 26건 (29.2%)
❌ 재생성이 필요합니다.
```

## 검사에도 순서가 있습니다 ★

!!! quote "이 교재를 만들 때 실제로 겪은 일"
    누수 검사를 먼저 돌렸더니 **4건 중 3건이 오탐**이었습니다.

    검은 프레임끼리는 지문이 똑같아서, 서로 누수로 잡힌 것입니다.
    퇴화 프레임을 먼저 걸러내니 실제 누수 1건만 남았습니다.

```python
# 검은·단색 프레임은 §3 에서 이미 보고했으므로 누수 검사에서 제외한다
degenerate = {id(it) for it in (*black, *uniform)}
candidates = [it for it in items if id(it) not in degenerate]
```

**검증기도 검증해야 하고, 검사에는 전제와 순서가 있습니다.**
기초 과정 7H 에서 배운 것과 같은 이야기입니다.
