# 13H · 학습 실행

!!! warning "이 시간의 실습은 최종 검증 전입니다"
    러너 API 는 RSL-RL 버전에 따라 다릅니다.
    실패하면 스크립트가 **표준 경로**(Isaac Lab 제공 train.py)를 안내합니다.

**실습 스크립트**: `course_b/day2/20_train.py`

## 학습 목표

- 병렬 환경 수와 VRAM 의 관계를 안다
- 학습을 걸고 **기다리지 않는 법**을 안다

---

## 병렬 환경 수 ★

강화학습은 **경험이 많을수록** 잘 배웁니다.

| 병렬 환경 수 | VRAM | 특징 |
|---|---|---|
| 64~256 | 적음 | 디버깅용. 느리고 불안정 |
| **1024** | 중간 | **16GB 에서 무난한 출발점** |
| 4096 | 많음 | 빠르지만 16GB 로는 씬에 따라 부족 |

```bash
./isaaclab.sh -p 20_train.py --num-envs 1024 --iterations 300
```

!!! danger "`CUDA out of memory` 가 나면 절반으로 줄이세요"
    ```bash
    ./isaaclab.sh -p 20_train.py --num-envs 512 --iterations 300
    ```

!!! note "환경을 2배 늘려도 학습 시간이 절반이 되지는 않습니다"
    수렴에 필요한 **총 스텝 수**가 줄어드는 것이지 공짜가 아닙니다.
    한 번의 갱신에 더 많은 데이터를 쓰는 것이므로 갱신 횟수 자체는 비슷합니다.

---

## 하이퍼파라미터는 나중에 ★

!!! danger "학습이 안 될 때 하이퍼파라미터부터 만지지 마세요"
    **첫 번째로 의심할 것은 보상 설계**입니다 (12H).

    수강생 대부분이 여기서 몇 시간을 허비합니다.
    학습률을 열 번 바꾸는 것보다 보상 항 하나를 고치는 게 빠릅니다.

기본 설정을 그대로 쓰세요.

```python
"algorithm": {
    "class_name": "PPO",
    "learning_rate": 1.0e-3,
    "entropy_coef": 0.005,      # 탐험 정도. 낮으면 조기 수렴
    "gamma": 0.99,              # 미래 보상 할인. 과제가 길면 0.995
    "desired_kl": 0.01,
},
```

| 파라미터 | 언제 건드리나 |
|---|---|
| `learning_rate` | 곡선이 발산할 때 낮춤 |
| `entropy_coef` | 조기 수렴이 의심될 때 높임 |
| `gamma` | 에피소드가 매우 길 때 |

## 걸어 두고 넘어가세요 ★

학습은 몇십 분씩 걸립니다.

```bash
# 백그라운드로 걸고 로그만 확인
./isaaclab.sh -p 20_train.py --num-envs 1024 --iterations 300 > train.log 2>&1 &
tail -f train.log
```

!!! success "끝나기를 기다리지 마세요"
    14H 노트북이 **4가지 학습 양상을 흉내 낸 모의 로그**를 만들어 줍니다.
    자기 결과가 없어도 진단을 배울 수 있고,
    15H 쯤 자기 학습이 끝나면 그걸로 평가하면 됩니다.

## 남는 것

```
_out/runs/sorting_v1/
├─ train_log.jsonl      ← 반복별 지표 (14H 노트북이 읽음)
├─ meta.json            ← 실행 조건·러너 설정
├─ model_*.pt           ← 체크포인트
└─ (tensorboard 로그)
```

!!! tip "`train_log.jsonl` 을 따로 남기는 이유"
    TensorBoard 를 못 쓰는 상황(원격·방화벽·포트 차단)에서도
    학습 상태를 볼 수 있게 하기 위해서입니다.

!!! warning "`meta.json` 을 체크포인트와 함께 보관하세요"
    학습 때 쓴 러너 설정이 없으면 **정책을 복원할 수 없습니다.**
    15H 에서 필요합니다.
