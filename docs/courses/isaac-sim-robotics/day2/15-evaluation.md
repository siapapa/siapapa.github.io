# 15H · 정책 평가 — 곡선이 올라간 것 ≠ 잘하는 것

!!! warning "재생 스크립트는 최종 검증 전입니다"
    `22_play_eval.py` 는 Isaac Sim 이 필요합니다.

!!! success "리포트 노트북은 검증 완료 · GPU 불필요"
    `23_eval_report.ipynb` 는 모의 결과로 판정 연습을 할 수 있습니다.

**실습 자산**: `22_play_eval.py` · `23_eval_report.ipynb`

## 학습 목표

- 보상이 아니라 **과제 지표**로 잰다
- 성공률만 보지 않는다
- 배포 판단을 근거와 함께 말한다

---

## 학습 곡선이 알려주지 않는 것 ★

곡선은 **"정책이 보상을 잘 먹는다"** 만 알려 줍니다.
보상 설계가 틀렸다면 **보상을 잘 먹는 잘못된 행동**을 학습한 것입니다.

반드시 두 가지를 모두 하세요.

1. **눈으로 본다** (`--gui`) — 이상한 동작을 하는지
2. **과제 고유 지표로 잰다** — 보상이 아니라 성공률·소요시간

```bash
./isaaclab.sh -p 22_play_eval.py --checkpoint _out/runs/sorting_v1/model_300.pt --gui
```

## 성공률만 보면 안 됩니다 ★

리포트 노트북이 정책 3개를 비교합니다.

```
정책                   성공률      평균보상     평균길이     행동크기     보상편차
baseline               42.0%       6.10      118.0       0.31       1.22
tuned_reward           87.0%      12.40       63.0       0.44       2.48
aggressive             91.0%      15.80       51.0       0.93       3.16
```

판정:

```
정책               판정       근거
baseline           ❌ 부적합   성공률 42% — 실용 수준 미달
tuned_reward       ✅ 채택 가능 성공률 87%, 행동 0.44, 안정성 양호
aggressive         ⚠️  보류     행동 크기 0.93 > 0.8 — 실기 이식 위험

권장: tuned_reward  (판정 채택 가능, 성공률 87%)
```

!!! warning "가장 성공률이 높은 정책이 최선은 아닙니다"
    `aggressive` 는 91% 로 가장 높지만 **행동 크기가 0.93** 입니다.

    실제 로봇에 옮기면 기구부에 무리가 가고, 사람 근처에서 위험합니다.
    87% 인 `tuned_reward` 가 실무적으로 낫습니다.

| 지표 | 왜 보는가 |
|---|---|
| 성공률 | 과제를 해내는가 |
| **행동 크기** | 실기 이식 시 안전·수명 |
| **보상 변동계수** | 결과가 들쭉날쭉하면 신뢰 불가 |
| 평균 길이 | 얼마나 빠른가 |

!!! success "발표에서 점수를 받는 지점이 바로 이 판단입니다"
    **"성공률 91% 정책 대신 87% 를 택했고, 이유는 이렇습니다"**
    를 설명할 수 있어야 합니다.

## 발표용 요약 문장

```
■ 정책: tuned_reward
■ 성공률 87% (에피소드 1,280회, 기준: 목표 반경 5cm 이내 도달)
■ 평균 소요 63스텝 (최대 150스텝 중)
■ 한계: 행동 크기 평균 0.44 — 실기 이식 전 부드러움 튜닝 필요
```

!!! note "'평균 보상 12.4' 라고 하면 아무도 감흥이 없습니다"
    **"성공률 87%, 평균 4.2초"** 라고 해야 의미가 전달됩니다.
