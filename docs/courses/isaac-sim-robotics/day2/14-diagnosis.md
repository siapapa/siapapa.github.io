# 14H · 학습 곡선 읽기

!!! success "이 시간은 실행 검증 완료 · GPU 불필요"
    로그 파일만 읽습니다. 학습이 안 끝났어도 **모의 로그**로 진행됩니다.

**실습 노트북**: `course_b/day2/21_training_monitor.ipynb`

## 학습 목표

- 4가지 학습 상태를 곡선으로 판별한다
- **지표 하나로 판단하지 않는** 습관을 들인다

## 왜 곡선을 읽나

학습은 몇십 분씩 걸립니다. 다 기다렸다가 "안 됐네" 하고 다시 돌리면
하루가 갑니다. **곡선을 읽으면 5분 만에 판단**할 수 있습니다.

## 4가지 상태

| 상태 | 곡선 모양 | 원인 | 조치 |
|---|---|---|---|
| **정상** | 꾸준히 상승 후 완만 | — | 계속 |
| **정체** | 초반부터 평평 | 보상이 신호를 못 줌 | **보상 재설계** |
| **발산** | 올랐다가 무너짐 | 학습률·클리핑 | lr 낮춤 |
| **보상 해킹** | 보상만 급등, 길이 이상 | 의도 안 한 요령 | 보상 항 점검 |

노트북이 네 상태를 흉내 낸 모의 로그를 만들어 줍니다.

## 진단 규칙에도 순서와 전제가 있습니다 ★

!!! quote "이 교재를 만들 때 실제로 겪은 일"
    진단기가 평평한 `stuck` 곡선에 **"발산"까지** 붙였습니다.

    평평한 곡선에서는 눈에 보이는 진폭이 **전부 노이즈**인데,
    그 위에 "최고점 대비 하락" 규칙을 적용했기 때문입니다.

고친 방법:

```python
# 정체로 판정되면 거기서 끝낸다 — 평평한 곡선에 다른 규칙을 적용하면
# 노이즈를 발산으로 오독한다
if abs(r1 - r0) < 0.05 * max(abs(r0), abs(r1), 1.0):
    return [("정체", ...)]

# 발산은 '올랐다가 무너졌다' 이므로, 먼저 실제로 올랐는지 확인한다
actually_rose = peak - r0 > 0.3 * span
if actually_rose and r1 < peak - 0.35 * span and v1 > v0:
    ...
```

**규칙을 적용하기 전에 그 규칙의 전제가 성립하는지 봐야 합니다.**
