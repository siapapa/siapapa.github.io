# 11H · 관측과 행동

!!! warning "이 시간의 실습은 최종 검증 전입니다"

**실습 스크립트**: `course_b/day2/19_sorting_env.py`

## 학습 목표

- 관측 설계 3원칙을 안다
- 행동을 **증분**으로 주는 이유를 안다

---

## 관측 설계 3원칙 ★

### ① 필요한 것은 반드시 넣는다

!!! danger "목표까지의 상대 위치가 없으면 정책은 목표를 알 수 없습니다"
    **"왜 학습이 안 되지?" 의 가장 흔한 원인입니다.**

    정책은 관측만 보고 행동합니다. 관측에 없는 정보는
    **존재하지 않는 것과 같습니다.**

### ② 불필요한 것은 넣지 않는다

차원이 늘수록 학습이 느려집니다.
그리고 **절대 좌표보다 상대 좌표**를 주세요.

| | 문제 |
|---|---|
| 절대 좌표 | 정책이 "이 위치에서는 이렇게"를 외움 → 목표가 바뀌면 못 함 |
| 상대 좌표 | "목표 쪽으로 가라"를 배움 → 일반화됨 |

### ③ 스케일을 맞춘다

관절각(±3 rad)과 속도(±20 rad/s)를 그대로 섞으면
**큰 값이 학습을 지배합니다.**

```python
joint_pos = L.ObsTerm(func=mdp.joint_pos_rel)
joint_vel = L.ObsTerm(func=mdp.joint_vel_rel, scale=0.1)   # 스케일 보정
last_action = L.ObsTerm(func=mdp.last_action)
```

또는 러너 설정에서 `empirical_normalization=True` 로 자동 정규화할 수 있습니다.

!!! note "`last_action` 을 넣는 이유"
    직전에 취한 행동을 알려 주면 정책이 **자기 움직임의 연속성**을
    알 수 있습니다. 떨림을 줄이는 데 도움이 됩니다.

---

## 행동 — 절대각이 아니라 증분 ★

```python
joint_pos = mdp.JointPositionActionCfg(
    asset_name="robot",
    joint_names=[".*"],
    scale=0.5,                    # 한 스텝 최대 변화량
    use_default_offset=True,
)
```

!!! danger "절대각을 주면 물리가 터집니다"
    정책이 한 스텝에 로봇을 **순간이동**시키려 합니다.
    관절이 순식간에 움직이면 물리 엔진이 발산합니다.

    증분으로 주고 `scale` 로 제한하세요.

| scale | 증상 |
|---|---|
| 너무 큼 | 진동, 학습 불안정 |
| 너무 작음 | 시간 안에 목표 도달 실패 |

## 관측 차원 확인

```
관측 차원: (16, 27)   (환경 수, 관측 길이)
행동 차원: 9
```

!!! tip "항을 하나씩 주석 처리해 보세요"
    차원이 어떻게 바뀌는지 보면 각 항이 몇 개의 값을 내는지 알 수 있습니다.
    나중에 "관측이 이상하다" 싶을 때 이 감각이 도움이 됩니다.

## 정리

| 원칙 | 한 줄 |
|---|---|
| ① 필요한 것은 넣는다 | 관측에 없으면 존재하지 않는 것 |
| ② 불필요한 것은 뺀다 | 절대 좌표보다 상대 좌표 |
| ③ 스케일을 맞춘다 | 큰 값이 학습을 지배함 |
| **행동은 증분** | 절대각은 물리를 터뜨림 |
