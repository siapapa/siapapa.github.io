# 12H · 보상·종료 설계

!!! warning "이 시간의 실습은 최종 검증 전입니다"

**실습 스크립트**: `course_b/day2/19_sorting_env.py`

!!! success "이 과정의 승부처입니다"
    강화학습이 안 되는 이유의 대부분은 하이퍼파라미터가 아니라
    **보상 설계**입니다.

## 학습 목표

- 보상 해킹 사례를 알아본다
- 주 보상과 정규화 항을 구분해 설계한다
- `time_out` 과 실패 종료를 구분한다

---

## 먼저 실패를 봅니다 ★

로봇이 기행을 벌이는 대표적인 이유들입니다.

| 잘못된 보상 | 로봇이 배우는 것 |
|---|---|
| 목표에 가까우면 +1 (도달 종료 없음) | 목표 근처에서 **떨면서** 보상을 계속 먹음 |
| 빨리 도달하면 큰 보상만 | 물리를 뚫고 지나가는 **폭력적인 해** |
| 페널티만 잔뜩 | **아무것도 안 하는 게 최선** → 정지 |
| 항이 너무 많음 | 어느 항이 문제인지 **진단 불가** |

!!! quote "정책은 여러분이 준 보상을 최대화합니다"
    여러분이 **원한 것**을 하는 게 아닙니다.
    이 둘이 다르면 로봇은 원치 않은 쪽을 정확히 찾아냅니다.

---

## 설계 4원칙

### ① 주 보상은 하나로 명확히

"목표에 도달했는가" 하나입니다. 나머지는 전부 보조입니다.

### ② 나머지는 정규화 항, 가중치는 작게

```python
alive = L.RewTerm(func=mdp.is_alive, weight=1.0)

joint_vel_penalty   = L.RewTerm(func=mdp.joint_vel_l2,     weight=-1e-4)
action_rate_penalty = L.RewTerm(func=mdp.action_rate_l2,   weight=-1e-3)
joint_limit_penalty = L.RewTerm(func=mdp.joint_pos_limits, weight=-0.1)
```

| 항 | 억제하는 것 |
|---|---|
| `joint_vel_l2` | 과도하게 빠른 움직임 |
| `action_rate_l2` | 떨림(chattering) |
| `joint_pos_limits` | 관절 한계에 붙는 것 (기구부 손상) |

**전부 음수 가중치이고, 주 보상보다 훨씬 작습니다.**

### ③ 항을 꺼 가며 실험할 수 있게 쪼갠다

Manager-based 를 쓰는 이유가 여기 있습니다.
한 항의 가중치를 0 으로 두고 돌려 보면 그 항의 역할이 보입니다.

### ④ 스케일을 맞춘다

한 항이 다른 항을 압도하면 나머지는 무의미합니다.
학습 중 각 항의 기여도를 로그로 확인하세요.

## 거리 보상의 형태 ★

```
선형   -d              멀 때 기울기가 약해 초기 학습이 느림
지수   exp(-d²/σ²)     가까울수록 급격히 커져 학습이 잘 됨   ← 권장
```

!!! tip "왜 지수 형태가 나은가"
    선형 보상은 멀리 있을 때나 가까이 있을 때나 기울기가 같습니다.
    정책 입장에서 "조금 가까워진 것"의 이득이 늘 똑같아 신호가 약합니다.

    지수 형태는 가까워질수록 이득이 커져 **마무리를 잘하게** 만듭니다.

---

## 종료 — `time_out` 과 실패를 구분하세요 ★

```python
time_out = L.DoneTerm(func=mdp.time_out, time_out=True)     # ← 플래그 주의
```

| | 의미 |
|---|---|
| **시간 초과** | "아직 못 했을 뿐" |
| **실패 종료** | "잘못했다" |

!!! danger "둘을 같게 처리하면"
    정책이 **시간 초과를 피하려고 자멸하는 법**을 배웁니다.
    빨리 실패해서 에피소드를 끝내는 것이 이득이 되기 때문입니다.

    Isaac Lab 은 `time_out=True` 플래그로 이를 구분합니다.
    부트스트랩 계산(bootstrapping)에서 다르게 처리됩니다.

!!! warning "종료 조건이 아예 없으면"
    한 판이 끝나지 않아 **학습이 시작되지 않습니다.**
    최소한 `time_out` 은 반드시 있어야 합니다.

## 정리

| 항목 | 핵심 |
|---|---|
| **주 보상 하나** | 나머지는 정규화, 가중치 작게 |
| **지수 형태** | 가까울수록 급격히 커지게 |
| **항으로 쪼개기** | 꺼 보며 진단할 수 있게 |
| **`time_out` 구분** | 안 하면 자멸을 배움 |
| **보상 = 정책의 목표** | 원한 것과 다르면 원치 않은 쪽을 찾아냄 |
